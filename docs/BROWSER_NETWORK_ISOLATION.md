# 浏览器环境与网络隔离改进计划 v3

本版替代 v2，当前仍在实施中。2026-10-08 根据首版代码审查补充兼容要求和原型验收项。本文描述目标与门槛，不代表所列功能均已实现；实际能力见 [NETWORK_ISOLATION_PROGRESS.md](NETWORK_ISOLATION_PROGRESS.md)。M1 未通过前不得开放严格保护。

2026-10-08 原型发现冷 WSS 不触发当前 CDP Fetch 认证，同版本 Chromium 源码支持这一限制。共享 Chrome 加 CDP 认证路线尚不满足 M1；替代路径的取舍和需修订的边界见 [冷 WSS 方案评估](COLD_WSS_AUTHENTICATION_REVIEW.md)。本文以下仍保留 v3 原目标，未暗中切换架构或降低验收要求。

## 产品与范围

每账号独立 Profile、每分组指定出口，单账号独享出口通过单账号分组实现；节点不同不保证公网 IP 不同。环境/基础诊断覆盖现有平台，严格保护首版 Windows 11 x64。新旧分组默认普通模式，严格模式显式开启；组件失效/节点缺失则阻断，不降级。

普通模式保留 gw.alipayobjects.com、sv.creditcard.ecitic.com 两个付款直连例外并展示；不新增第三模式。严格模式取消例外，切模式先关闭浏览器。不创建 TUN、不修改系统代理、默认路由和全机 DNS。Chrome 禁外部直连/UDP，代理协议必要 UDP 单独放行。

威胁模型是正常应用误配置、故障、意外绕过，不抵抗管理员/恶意软件/不可信上游，不承诺完全替代指纹浏览器或零风控。取消卡死5秒冻结/休眠立即失效硬要求；原规则持续约束，控制失联不批准新启动/配置提交。

## 受管运行时、WFP 和认证

同一应用数据目录内，各严格分组共用一份项目专用 Chrome，账号继续使用各自的 Profile。普通模式与日常 Chrome 使用原安装路径。专用 Chrome 从本机安装目录完整复制，不修改二进制，也不使用源目录硬链接。活动路径保持固定，候选更新存放在独立暂存目录；替换前先预览影响范围，并关闭所有使用该副本的实例。

路径迁移必须验证 Cookie、Local Storage、IndexedDB、重启和合成登录态。首版可以仅支持经过检查的非应用绑定加密 Profile：迁移前检查 Local State 和 Cookie 密文格式，遇到应用绑定加密、损坏或无法判断的数据就拒绝迁移。不能仅凭缺少 `app_bound_encrypted_key` 就认定安全，也不能关闭加密、清空 Profile 或长期停止 Chrome 更新来通过验证。只读格式守卫已有实验实现，生产准入锁、真实迁移及版本升级兼容仍需实现和验收；不要求首版支持 v20 迁移。Chromium 当前对非默认用户数据目录限制应用绑定加密，但发行版本仍需单独验证。[Chromium 实现](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/os_crypt/app_bound_encryption_win.cc)

每个严格分组使用独立的 mihomo 进程、可执行路径、配置目录、入口端口和随机凭据；候选配置使用新的代次路径与端口。Chrome 和 mihomo 以当前用户身份运行，生命周期由 broker 的 Job 管理。保留四浏览器并发上限；分组最后一个浏览器退出后，代理空闲 60 秒回收。每组最多额外保留一个候选实例。

新增精简的 .NET NativeAOT 网络管理服务及提权安装器，首版使用 Windows 自带 WFP 过滤能力，不包含自研驱动。程序和受管二进制放在管理员保护目录，校验安装产物和固定版本哈希；运行配置及凭据保留在对应用户的数据边界。服务使用受限身份与 Service SID，由安装器授予必要的 WFP 权限。

服务的命名管道验证调用者身份、用户、登录会话，以及 Agent 与 broker 的所属关系。不同用户和数据目录的授权不得混用。接口仅允许登记、应用策略、冻结、查询和释放已登记资源，不提供任意命令、任意文件路径或通用进程控制能力。

持久化规则默认阻断，动态 WFP 会话承载放行规则，因此默认阻断不依赖管理服务存活。规则必须通过 WFP 事务更新，并验证私有子层权重与现有防火墙的关系；不得用全局强制放行覆盖其他策略的阻断。

项目严格 Chrome 只能访问已登记的严格代理入口及必要控制通道，不能放行整个回环网络。每组 mihomo 只能连接本组批准的上游地址、端口和协议；浏览器的 UDP 禁止规则不套用到代理协议必要的 UDP。受管目录中的辅助程序需要建立版本化清单并验证实际网络行为，不能假定只约束一个文件就覆盖所有程序。入站监听及接收同样需要限制，保留精确的本地 CDP 通道并验证不会误拦代理回复。

入口端口同时设置监听归属限制。分配前查询实际 IPv4/IPv6 动态端口范围、排除范围及占用情况，不能只硬编码“小于 49152”。持久化绑定规则的作用范围、升级和回收必须纳入生命周期管理；释放端口前先确认对应进程及连接清理，再撤销相关规则。冲突时更换候选端口，不终止其他软件。BFE、规则或组件状态无法确认时，拒绝新的严格启动。

每个代理配置代次生成随机凭据，随启动快照绑定账号、分组、入口及配置版本。认证处理不能根据挑战端口临时查询其他组的密码。listener 必须显式设置非空 `users`，配置校验拒绝代表免认证的空列表。

有头与后台启动统一安装代理认证处理，只向匹配预期入口的 Proxy 挑战提供凭据，网站 Server 挑战不得收到代理密码。身份、环境和认证初始化应由统一协调器处理，在必要设置完成后统一恢复目标；必须验证与 Playwright 自动附加的交互，不能只测试两套独立屏障各自运行。认证安装失败、重复认证失败或关键 CDP 通道失效时，停止启动或关闭实例。

原型覆盖新页面、跨站 iframe、Worker、HTTPS CONNECT、WebSocket、认证缓存和 CDP 断开。请求拦截性能先以可重复的本地页面比较，再补业务页面测试，并分别验证断连、连接无响应和 Agent 卡死。请求暂停不是 WFP 已冻结的证据。凭据轮换、账号换组和端口复用必须经过关闭流程，不能以修改密码代替旧连接撤销。此方案通过认证在公网转发前拒绝错误分组凭据，不宣称 WFP 已实现逐账号进程隔离。

## 配置与故障

严格实例由受控模板生成，只包含选定节点，内部代理名固定为 `upstream`，listener 显式指向它，兜底规则为 `MATCH,REJECT`。禁用业务 DIRECT 和其他节点回退，并拒绝跳过证书校验的配置。Chrome 使用数值回环代理地址，两条启动路径统一验证 `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1`，保留 WebRTC 原生偏好并取消付款 bypass；隐式回环绕过由 WFP 精确限制。

业务 DNS 默认使用经节点的 `https://1.1.1.1/dns-query#upstream`，不启用直连 fallback 或 H3 优先。管理侧仅为节点地址做初始解析；运行配置固定到批准的数值 IP，并保留原域名的证书校验、SNI 和传输 Host 语义，mihomo 无需额外的公网 bootstrap DNS 放行。多 IP 在候选准备阶段选择并验证，运行期间发现新地址只能生成候选，不能直接扩大现有权限；替换经过变更协调器。

协议矩阵覆盖现有 AnyTLS、Hysteria2、TUIC、VLESS/XHTTP、VMess/WebSocket，以及 HTTP、HTTPS、SOCKS5 自定义节点。每类协议都要验证完整的外部连接集合。无法确定连接目标的链式代理、外部插件、动态端口或额外传输端点，在严格模式明确标为不支持；普通模式保持兼容。

冻结同时撤销 Chrome 到该组入口、该组 mihomo 到上游两段的放行，避免代理继续发送已接收的缓冲数据。WFP 事务成功及重新授权提供网络阻断依据，BrowserRun/Job 提供进程关闭证明，两者分别记录；已经发送的数据无法撤回。动态会话在服务退出后的清理行为必须实测，不预先承诺固定毫秒数。

服务或 Agent 卡死时允许既有已批准链路继续工作，但不批准新启动或配置提交，界面显示“控制异常”，不能未经确认显示“已阻断”。休眠恢复后复核规则、组件及配置版本，不因恢复失败扩大权限。不定期探测 chatgpt.com，运行健康主要依据进程、规则和实际连接错误；公网诊断由用户触发。失败恢复不得自动重发结果不确定的付款、对话或其他网页操作。

## 协调、环境、迁移与 IPC

统一变更协调器覆盖节点编辑、订阅刷新、启停、分组绑定与删除、账号换组、保护模式切换及受管运行时更新。固定顺序如下：

1. 预览活动实例/版本，明确关闭并应用。
2. 预留资源并关闭准入，重叠RESOURCE_BUSY。
3. 原子持久化commandId/operationId/回执/prepared日志，才执行外部动作。
4. 撤销排队许可、冻结两端、关闭Chrome、Job清零、清理代理。
5. 准备候选，失败清理并保持暂停。
6. SQLite事务提交配置/版本/阶段，发布映射、清旧资源、开放准入。

变更日志至少区分 `prepared / frozen / drained / candidate_ready / committed / completed / failed`。不持有 SQLite 事务等待外部进程，也不持有关闭回调需要的锁。OperationRegistry 只负责展示，恢复使用独立的持久化日志；日志写入失败就停止推进，普通回执过期后也不得重放同一网络变更命令。

重启时先处理日志：未提交使用旧配置，已提交使用新配置；两者都回收遗留实例，并保持相关组暂停，等待明确恢复。`close_failed` 不释放账号隔离，也不提交切换。旧修改接口在影响活动受保护资源时，必须在写库前返回 `RESOURCE_BUSY` 或进入协调器，不能绕过版本和资源检查。

新旧账号默认继承分组，保留既有分组手动设置与自动探测逻辑；换组后在下次启动应用新值。账号固定模式显式保存自己的语言和时区，不随出口或分组变化覆盖；恢复继承是单独操作，不删除 Profile。每次运行使用不可变快照，修改只影响下次启动，界面显示待生效状态。

兼容修订：未配置或探测未得到的值保留旧启动默认。语言继续使用应用原有的 `zh-CN`，时区不传覆盖值，由 Chrome 决定；不能把 Node 的 Intl 结果当成 Chrome 已确认的环境。已探测到的部分值仍然保留，失败后允许重试。查询不触发公网探测；地区尚不完整时明确标为启动前待探测，不承诺当前预览就是最终值。

继承模式的普通有头窗口保持原有时区设置与关闭行为，不因语言默认值存在就启用新的持续环境屏障。明确选择账号固定的 Windows broker 窗口才使用该屏障，初始化失败或关键控制连接失效时关闭实例。原有后台身份屏障继续保留，已配置地区在后台启动时应用。保留交互窗口最大化、后台默认视口和真实 Chrome UA/UA-CH，不增加设备特征伪造或未经验证的风控评分。

在 schema v6 之后追加迁移，逐阶段新增环境、分组保护策略、配置版本、强事务日志及诊断报告。旧分组保持普通模式，旧账号保持继承。迁移前停止写入、checkpoint 并创建一致性备份；数据库回退必须停机恢复配套备份，不自动覆盖最新数据，也不修改 Profile。

IPC 升至 1.4。环境接口为 `environments.get/update/reset`；目标网络接口为 `network.getCapabilities/getState`、`previewChange/applyChange`、`setGroupPolicy/resumeGroup`、`runDiagnostics/getDiagnostics`。未实现的接口不提前注册，也不返回虚构成功。环境预览通过 `probePending` 标识尚需探测，时区 `null` 表示不主动覆盖，不能显示为某个已验证时区。

旧 DTO、错误 envelope 和事件 `seq/revision` 保持不变，不按客户端过滤全局事件。修改使用 commandId 和版本校验。详情或操作进行中每 2 秒查询，其余活动界面每 10 秒，托盘停止；单类查询最多一个在途，失败退避至 30 秒。Desktop 和 Agent 配套发布，验证旧客户端连接新 Agent；新客户端遇旧 Agent 明确拒绝并提示升级。本机保护、控制异常及公网诊断结果分开展示。

## 验收与阶段

专用Windows测试环境/测试Profile，不解除真实账号保护做对照、不真实付款。覆盖：基线直连/DNS/UDP；首包/多组/日常Chrome；错凭据/A到B/空users/401/Worker/WS/缓存；端口抢占/复用；DIRECT/漏listener/DNS fallback/缓冲；八类协议/SNI/Host；崩溃/卡死/休眠/VPN；并发/各日志阶段崩溃/磁盘失败/重放；环境换组/更新/登录态；权限/多用户/IPC/升级卸载/SecureBoot/HVCI；四浏览器100次开关资源回收。

pktmon、WFP规则/审计、系统DNS为早期证据，记录范围与阳性对照，无日志/无UDP不单独证明通过。M3交付自部署HTTPS回显/权威DNS/受限DoH/STUN，随机标识、不传账号凭据，本地7天远端15分钟，未配置为未验证。
