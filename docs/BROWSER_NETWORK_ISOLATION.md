# 浏览器环境与网络隔离改进计划 v4

修订日期：2026-10-10；实施状态更新：2026-10-14。用户已接受“每个严格分组使用一份独立 Chrome 副本”。本版替代 v3 的共享 Chrome 与入口密码隔离路线，保留原产品边界、两端出口约束、环境管理、协调器和恢复要求。M1-A 已有[离线资源与配置模型](GROUP_PATH_PLAN.md)、规则内存编码、CDP 资源登记，以及目录/程序文件/端口的只读报告匹配；v4 的运行保护尚未实现或验收。真实能力见 [NETWORK_ISOLATION_PROGRESS.md](NETWORK_ISOLATION_PROGRESS.md)，M1 未通过前不得开放严格保护。

修订依据是 2026-10-08 复现的冷 WSS 认证失败及同版本 Chromium 源码，见 [冷 WSS 方案评估](COLD_WSS_AUTHENTICATION_REVIEW.md)。旧路线的失败证据仍然保留，不将其改记为通过；新路线必须重新验证冷 HTTP/HTTPS/WS/WSS 和分组隔离。

## 本版决策与行为变化

| 项目 | v3 | v4 |
| --- | --- | --- |
| 严格 Chrome | 同一数据目录共用一份程序副本 | 每个严格分组一份完整副本；组内账号共用程序、各自使用独立 Profile |
| 分组隔离 | 共用程序可连接登记入口，靠入口凭据区分组 | WFP 按本组程序路径、运行用户及精确入口限制；A 组不能连接 B 组入口 |
| 浏览器入口认证 | 必须有非空 `users`，由 CDP 应答 | 经完整 WFP 保护的专用回环入口不向 Chrome 要求密码；其他输入仍拒绝免认证降级 |
| 其他程序访问入口 | 主要依赖密码拒绝 | 对已预留入口实施客户端默认拒绝；普通 Chrome、其他组和未登记程序均不能使用该入口 |
| CDP 职责 | 环境、身份和代理密码 | 环境、身份及生命周期；不再为代理认证暂停所有请求，不向页面注入代理密码 |
| 更新成本 | 一次更新影响所有严格组 | 按组关闭和替换，磁盘占用随已配置严格组数量增长；公共依赖变更仍需预览全部影响 |

“每组独立”不等于每账号拥有 WFP 进程身份。同组账号共享网络权限，账号隔离仍由 Profile、启动快照和 BrowserRun/Job 保证。需要单账号独享出口时使用单账号分组。

## 产品与范围

维护范围更新（2026-10-13）：客户端只维护当前 `app/` 下的 Tauri；`desktop/` 的 Avalonia 客户端停止维护，不纳入本计划的新功能、兼容适配或验收。Agent、Chrome broker 和独立 .NET 网络组件继续维护。

签名决策更新（2026-10-14）：用户明确本程序不需要 Windows 代码签名。本项目客户端、broker、网络工具及后续管理服务/安装器不以 Authenticode、购买代码签名证书或签名资格为开发和验收前提。保留安装产物的固定版本/哈希、管理员目录 ACL 和调用者身份核对；第三方 Chrome 已有发布者签名的来源核验不等于为本程序购买或添加签名，也不要求所有第三方文件均有 Authenticode。Tauri updater 更新包签名继续保留，它使用项目自己的密钥，与 Windows 代码签名不同，见 [Tauri 更新签名说明](https://v2.tauri.app/zh-cn/plugin/updater/)。当前发布工作流仍有 Windows Authenticode 硬门槛，后续发布调整须取消该强制要求，同时保留 updater 和其它现有验收要求；本次仅修订计划，尚未修改发布工作流。

每账号独立 Profile、每分组指定出口，单账号独享出口通过单账号分组实现；节点不同不保证公网 IP 不同。环境/基础诊断覆盖现有平台，严格保护首版 Windows 11 x64。新旧分组默认普通模式，严格模式显式开启；组件失效/节点缺失则阻断，不降级。

普通模式保留 gw.alipayobjects.com、sv.creditcard.ecitic.com 两个付款直连例外并展示；不新增第三模式。严格模式取消例外，切模式先关闭浏览器。不创建 TUN、不修改系统代理、默认路由和全机 DNS。Chrome 禁外部直连/UDP，代理协议必要 UDP 单独放行。

威胁模型是正常应用误配置、故障、意外绕过，不抵抗管理员/恶意软件/不可信上游，不承诺完全替代指纹浏览器或零风控。取消卡死5秒冻结/休眠立即失效硬要求；原规则持续约束，控制失联不批准新启动/配置提交。

## 受管运行时与路径身份

每个严格分组按“用户 SID、应用数据目录登记 ID、不可变分组 ID”分配独立程序目录，不能用可变分组名称或用户传入路径直接拼接权限资源。示意布局为管理员保护根目录下的 `<installationId>/<groupId>/chrome/active/`；Profile 留在原用户数据边界，不复制进程序目录。普通模式与日常 Chrome 继续使用原安装路径。服务生成并登记规范路径，拒绝跨组路径复用、目录穿越、符号链接、junction 和其他重解析跳转；每次启动都核对实际程序、所属组、Profile 和运行用户。

严格 Chrome 从本机 Google Chrome 安装目录完整复制，不修改二进制，不使用源目录或组间硬链接。校验来源、可验证的签名、版本和完整文件清单；复制中源目录发生更新时放弃该候选并重新准备。WFP 的路径匹配不是文件完整性验证，仍须管理员目录 ACL、哈希和清单防止替换。所有 `.exe`（包括辅助程序）纳入默认阻断，只有确需联网的主程序获得本组入口权限。

分组活动路径保持固定；候选更新使用同一受保护卷上的独立暂存目录。替换前关闭该组所有浏览器并确认 Job 清零，不覆盖运行中的文件。第一版串行处理 Chrome 副本更新，全应用最多一个待替换候选和一个待清理旧副本；每组代理最多额外存在一个候选实例。其他未受影响分组可继续运行，服务或公共策略更新需要另行预览全部受影响组。

候选和保留旧目录默认不允许运行用户执行；活动目录只有完成程序登记、完整性检查和默认阻断后才获得执行准入。卸载或删除资源时先关闭准入、冻结并确认 Job 清零，再删除副本并清理本应用拥有的规则和端口登记；删除失败就保留默认阻断和待清理记录，不能提前移除保护或删除其他软件的策略。

首次启用严格模式才准备该组副本，不为普通分组预先分配。准备前测量源目录大小，预览“现有副本总量＋候选副本＋保留旧副本＋备份/临时空间＋安全余量”的峰值；空间不足就停止，不改用共享可执行路径。旧副本在提交、恢复记录和规则清理完成后回收；代理空闲回收不删除 Chrome 或 Profile。删除分组时只清理已登记且已证明无进程使用的程序资源，账号 Profile 不随之删除。

源 Chrome 更新后记录各组待更新版本并提供影响预览；已不在支持范围的版本暂停新的严格启动，不能为了避免迁移问题长期固定旧版本。磁盘占用和更新状态作为明确的用户信息展示，不承诺各副本能够共享磁盘或内存页。

路径迁移必须验证 Cookie、Local Storage、IndexedDB、重启和合成登录态，新增“原安装路径→A 组、A 组→B 组、组路径→普通路径、组内版本升级”矩阵。首版仅支持经过检查的非应用绑定加密 Profile：在持有账号准入锁且旧 Job 清零后，检查 Local State、Cookie 密文及 WAL；遇到应用绑定加密、损坏或无法判断的数据就拒绝迁移，不关闭加密、不清空 Profile、不长期停止 Chrome 更新。缺少 `app_bound_encrypted_key` 不能单独证明安全；已有只读守卫和一次副本实验也不代表新增路径已通过。

路径切换保持 Profile 目录和账号标识不变；回滚配置不等于允许旧 Chrome 打开已被新版本升级的 Profile。新版本一旦写入 Profile，除非已证明降级兼容，否则只能保留暂停并使用已验证版本恢复，不自动降级二进制或覆盖用户数据。

每个严格分组使用独立的 mihomo 进程、可执行路径、配置目录和入口端口；候选配置使用新的代次路径与端口。Chrome 和 mihomo 以当前用户身份运行，生命周期由 broker 的 Job 管理。保留四浏览器并发上限；分组最后一个浏览器退出后，代理空闲 60 秒回收并撤销动态放行。重启代理必须重新取得当前代次授权，不因沿用端口或程序路径跳过校验。

## WFP 与无密码入口的完整边界

新增精简的 .NET NativeAOT 网络管理服务及提权安装器，首版使用 Windows 自带 WFP 过滤能力，不包含自研驱动。程序和受管二进制放在管理员保护目录，校验安装产物和固定版本哈希；运行配置及凭据保留在对应用户的数据边界。服务使用受限身份与 Service SID，由安装器授予必要的 WFP 权限。

服务的命名管道验证调用者身份、用户、登录会话，以及 Agent 与 broker 的所属关系。不同用户和数据目录的授权不得混用。接口仅允许登记、应用策略、冻结、查询和释放已登记资源，不提供任意命令、任意文件路径或通用进程控制能力。

持久化规则默认阻断，动态 WFP 会话承载放行规则，因此默认阻断不依赖管理服务存活。规则必须通过 WFP 事务更新，并验证私有子层权重与现有防火墙的关系；不得用全局强制放行覆盖其他策略的阻断。

每组策略同时表达四个约束，缺少任何一个均不得开放无密码入口：

| 范围 | 默认行为 | 唯一可登记的放行 |
| --- | --- | --- |
| 本组 Chrome 和辅助 exe 出站 | 外部直连、UDP、其它组入口和未登记回环连接均阻断 | 本组主程序、所属用户到本组当前代次 `127.0.0.1:port/TCP`；额外控制通道逐条证明需要 |
| 本组专用入口的客户端 | 到预留入口的连接默认拒绝，覆盖普通 Chrome、其它组和未登记程序 | 本组已批准 Chrome 路径及用户；确需健康检查时仅授权受控诊断程序的精确资源 |
| 本组 mihomo 监听与接收 | 其它程序占用入口、通配地址或外部入站均拒绝 | 已登记 mihomo 路径及用户在精确 IPv4 回环入口监听和接收 |
| 本组 mihomo 出站 | DIRECT、额外 DNS 和其它上游均阻断 | 已批准上游 IP、端口和协议，包含所选代理协议必要的 UDP |

入口保护只作用于项目登记的端口，不能拦截系统所有回环连接或改变其他软件的代理行为。IPv6、IPv4 映射地址、其它回环地址、端口重用和回环流实际经过的过滤层均纳入测试；不能仅凭 `allow-lan: false` 或监听归属，就认定入口客户端已受保护。不得给通用 Agent HTTP 转发能力一个跨组入口白名单；受控诊断若需要特殊权限，必须独立登记且不接收任意业务转发目标。

候选使用 `ALE_AUTH_CONNECT` 实现连接限制，并组合 `ALE_RESOURCE_ASSIGNMENT`、`ALE_AUTH_LISTEN`、`ALE_AUTH_RECV_ACCEPT` 约束绑定、监听和接收。各层可用条件不同；接收端的本地应用路径不等于连接方的应用路径，不能拿它代替客户端侧的限制。具体条件、优先级与回环双向行为必须实测，[Microsoft ALE 层说明](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-layers)和[条件定义](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-condition-identifiers-)仅作为实现依据，不作为验收证明。

本地 CDP 端口属于另一类登记资源：限制 Chrome 的监听地址、允许连接它的 Agent/broker 身份和具体端口；不得给 Chrome 放行所有组的 CDP 端口。每次运行记录所属用户、登录会话、数据目录、组、账号、程序清单、入口、上游、策略版本和配置代次。不能单凭路径区分同一用户的不同登录会话，首版同一用户/数据目录只允许一个有写权限的 Agent 实例；其它会话不得重新接管活动资源。

入口端口同时设置监听归属限制。分配前查询实际 IPv4/IPv6 动态端口范围、排除范围及占用情况，不能只硬编码“小于 49152”。持久化绑定规则的作用范围、升级和回收必须纳入生命周期管理；释放端口前先确认对应进程及连接清理，再撤销相关规则。冲突时更换候选端口，不终止其他软件。BFE、规则或组件状态无法确认时，拒绝新的严格启动。

v4 受控模板使用独立标识 `isolationModel: group_path_v1`。仅这一模型允许本地 listener 明确配置为无密码（例如固定 mihomo 版本的 `users: []`）；普通订阅、任意配置和旧 v3 模型仍不能凭空列表绕过认证校验。编译配置不等于允许启动：服务确认持久化默认拒绝、入口客户端限制和绑定规则后，才允许该 mihomo 在 Job 内创建，再校验实际进程/端口归属，并以 WFP 事务放行批准的链路。服务或规则状态无法确认时无密码实例不得启动。

入口不再生成供 Chrome 使用的密码；上游节点自身的认证信息继续保留在受限配置中。监听端口变化、组绑定、账号换组和节点切换依然经过关闭流程；“没有密码需要轮换”不能代替旧连接撤销。

## CDP 与启动准入

有头与后台继续应用不可变身份/环境快照，并验证与 Playwright 自动附加的交互；移除仅为代理认证启用的全量 Fetch 暂停和密码应答。业务导航只在程序身份、WFP 规则、代理代次、Profile 锁和必要 CDP 设置全部确认后开始。未就绪时只允许初始空白页且网络仍受默认阻断，不能先导航再补规则。

关键控制连接断开或必要初始化失败时停止启动或关闭本次运行。网站 HTTP 401 交给正常浏览器行为，未知代理 407 或入口配置不符报告启动/运行错误，不查询其它组密码、不自动转为 DIRECT。需要身份与环境的目标仍须在最早脚本前应用设置，不因取消认证屏障删除这项保证。

原型重新覆盖新页面、跨站 iframe、dedicated/shared/service Worker、HTTPS CONNECT、WS/WSS、网络子进程重建和 CDP 断开。冷 HTTP/HTTPS/WS/WSS 必须在全新 Profile、无预先页面认证下完成；旧 v3 冷认证失败用例作为历史复现保留，另建 v4 测试，不改名或删除失败断言来制造通过。性能先比较可重复本地页面，再补业务页面基线；CDP 请求暂停和进程退出均不能代替 WFP 网络冻结证明。

## 配置与故障

严格实例由受控模板生成，只包含选定节点，内部代理名固定为 `upstream`，listener 显式指向它，兜底规则为 `MATCH,REJECT`。禁用业务 DIRECT、其他节点回退、未登记监听器和外部控制接口，并拒绝跳过证书校验的配置。Chrome 使用数值回环代理地址，两条启动路径统一验证 `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1`，保留 WebRTC 原生偏好并取消付款 bypass；隐式回环绕过由 WFP 精确限制。

业务 DNS 默认使用经节点的 `https://1.1.1.1/dns-query#upstream`，不启用直连 fallback 或 H3 优先。管理侧仅为节点地址做初始解析；运行配置固定到批准的数值 IP，并保留原域名的证书校验、SNI 和传输 Host 语义，mihomo 无需额外的公网 bootstrap DNS 放行。多 IP 在候选准备阶段选择并验证，运行期间发现新地址只能生成候选，不能直接扩大现有权限；替换经过变更协调器。

协议矩阵覆盖现有 AnyTLS、Hysteria2、TUIC、VLESS/XHTTP、VMess/WebSocket，以及 HTTP、HTTPS、SOCKS5 自定义节点。每类协议都要验证完整的外部连接集合。无法确定连接目标的链式代理、外部插件、动态端口或额外传输端点，在严格模式明确标为不支持；普通模式保持兼容。

冻结同时撤销 Chrome 到该组入口、该组 mihomo 到上游两段的动态放行，并保持入口客户端默认拒绝，避免代理继续发送缓冲数据。WFP 事务成功及[重新授权](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-re-authorization)提供网络阻断依据，BrowserRun/Job 提供进程关闭证明，两者分别记录；已经发送的数据无法撤回。动态会话在服务退出后的清理行为必须实测，不预先承诺固定毫秒数。服务崩溃后即使无密码 listener 进程仍存活，也必须无法被未授权客户端使用，且无法继续向上游发送业务数据。

服务或 Agent 卡死时允许既有已批准链路继续工作，但不批准新启动或配置提交，界面显示“控制异常”，不能未经确认显示“已阻断”。休眠恢复后复核规则、组件及配置版本，不因恢复失败扩大权限。不定期探测 chatgpt.com，运行健康主要依据进程、规则和实际连接错误；公网诊断由用户触发。失败恢复不得自动重发结果不确定的付款、对话或其他网页操作。

## 协调、环境、迁移与 IPC

统一变更协调器覆盖节点编辑、订阅刷新、启停、分组绑定与删除、账号换组、保护模式切换及受管运行时更新。固定顺序如下：

1. 预览活动实例、程序/策略版本、Profile 路径变化和磁盘峰值，由明确的“关闭并应用”处理活动窗口。
2. 预留账号、分组、程序路径和端口，关闭受影响资源的新任务准入；重叠变更返回 `RESOURCE_BUSY`。
3. 原子持久化 `commandId`、`operationId`、初始回执和 `prepared` 日志，成功后才执行外部动作。
4. 撤销排队启动许可，冻结两端，关闭受影响浏览器，确认 Job 清零，再清理旧代理连接。关闭失败不释放账号锁、不提交切换。
5. 准备候选程序/代理、批准地址、无密码入口保护及规则。候选只在明确登记的受限条件下使用新测试 Profile 验证，不提前打开账号真实 Profile，不能让生产 Chrome 同时访问新旧入口；失败清理候选并保持相关组暂停。
6. SQLite 事务提交新配置、运行时清单版本和提交阶段，随后发布运行映射、清理旧资源并开放准入。数据库事务不跨越外部进程等待。

第一版的最小影响范围如下；涉及共享节点或公共组件时取所有依赖组的并集，预览必须列出实际关闭的窗口。

| 变更 | 关闭与冻结范围 | 特别检查 |
| --- | --- | --- |
| 节点、入口或组内代理代次变化 | 使用该配置的全部分组 | 每组独立入口、批准上游和原子规则更新 |
| 单组 Chrome 更新 | 该组全部浏览器 | 旧 Job 清零、目录替换日志、完整清单、Profile 升级兼容 |
| 账号从 A 换到 B | 第一版保守冻结并关闭受影响严格源组和目标组；该账号的普通运行也须关闭 | 不复制 Profile；验证 A/B 程序路径切换和账号环境继承；同组其它账号的关闭影响明确展示 |
| 普通/严格模式切换、删除组 | 该组全部运行及关联资源 | 路径兼容、规则/端口回收、Profile 保留 |
| 管理服务或公共策略更新 | 所有使用该组件的严格组 | 版本协商、持久化默认拒绝和中断恢复 |

变更日志至少区分 `prepared / frozen / drained / candidate_ready / committed / completed / failed`。不持有 SQLite 事务等待外部进程，也不持有关闭回调需要的锁。OperationRegistry 只负责展示，恢复使用独立的持久化日志；日志写入失败就停止推进，普通回执过期后也不得重放同一网络变更命令。

重启时先处理日志：未提交使用旧配置，已提交使用新配置；两者都回收遗留实例，并保持相关组暂停，等待明确恢复。`close_failed` 不释放账号隔离，也不提交切换。旧修改接口在影响活动受保护资源时，必须在写库前返回 `RESOURCE_BUSY` 或进入协调器，不能绕过版本和资源检查。

Chrome 文件替换与 SQLite 不构成同一个事务。变更日志额外保存旧/候选/活动目录的清单哈希、预期版本和替换子阶段，在每次重命名前记录意图、完成后记录结果；重启时核对磁盘实际清单与数据库提交阶段。未提交可恢复已验证的旧目录，已提交恢复已验证的新目录；无法确认任一状态就保持阻断和暂停。已被新浏览器写入的 Profile 按前述降级限制处理，不通过恢复旧日志强行打开。

新旧账号默认继承分组，保留既有分组手动设置与自动探测逻辑；换组后在下次启动应用新值。账号固定模式显式保存自己的语言和时区，不随出口或分组变化覆盖；恢复继承是单独操作，不删除 Profile。每次运行使用不可变快照，修改只影响下次启动，界面显示待生效状态。

兼容修订：未配置或探测未得到的值保留旧启动默认。语言继续使用应用原有的 `zh-CN`，时区不传覆盖值，由 Chrome 决定；不能把 Node 的 Intl 结果当成 Chrome 已确认的环境。已探测到的部分值仍然保留，失败后允许重试。查询不触发公网探测；地区尚不完整时明确标为启动前待探测，不承诺当前预览就是最终值。

继承模式的普通有头窗口保持原有时区设置与关闭行为，不因语言默认值存在就启用新的持续环境屏障。明确选择账号固定的 Windows broker 窗口才使用该屏障，初始化失败或关键控制连接失效时关闭实例。原有后台身份屏障继续保留，已配置地区在后台启动时应用。保留交互窗口最大化、后台默认视口和真实 Chrome UA/UA-CH，不增加设备特征伪造或未经验证的风控评分。

现有环境管理已迁移至 schema 7；新模型从当前实际 schema 之后追加迁移，不重写已发布迁移。新增分组保护策略、隔离模型标识、不可变运行时登记、文件清单、策略/配置版本、强事务日志及诊断报告。旧分组保持普通模式，旧账号保持继承。迁移前停止写入、checkpoint 并创建一致性备份；数据库回退必须停机恢复配套备份，不自动覆盖最新数据，也不修改 Profile。

IPC 升至 1.4。环境接口为 `environments.get/update/reset`；目标网络接口为 `network.getCapabilities/getState`、`previewChange/applyChange`、`setGroupPolicy/resumeGroup`、`runDiagnostics/getDiagnostics`。未实现的接口不提前注册，也不返回虚构成功。环境预览通过 `probePending` 标识尚需探测，时区 `null` 表示不主动覆盖，不能显示为某个已验证时区。

旧 DTO、错误 envelope 和事件 `seq/revision` 保持不变，不按客户端过滤全局事件。修改使用 commandId 和版本校验。详情或操作进行中每 2 秒查询，其余活动界面每 10 秒，托盘停止；单类查询最多一个在途，失败退避至 30 秒。Tauri 客户端和 Agent 配套发布，验证仍受支持的旧 Tauri 客户端连接新 Agent；新客户端遇旧 Agent 明确拒绝并提示升级。本机保护、控制异常及公网诊断结果分开展示。

## v4 验收门槛

网络策略实测仅在专用 Windows 11 x64 测试环境中使用测试 Profile、测试节点和受控端点，不用真实付款做阳性对照。测试必须同时包含允许与拒绝的对照，保留程序、用户、路径、清单、端口、规则 GUID、版本和捕获范围。

| 验证组 | 必须通过的场景 |
| --- | --- |
| 现有基线 | 普通模式、绑定节点、两个付款例外、WebRTC、DNS、IPv6、QUIC；区分实测直连和潜在风险 |
| 路径与分组 | A→A 和 B→B 成功；A→B、B→A、普通 Chrome/未登记程序/其他用户→入口失败；辅助 exe、别名路径、重解析目录、错误 Profile/组快照拒绝 |
| 首次请求 | 全新 Profile 无预热的 HTTP、HTTPS CONNECT、WS、WSS；有头/后台、新页面、OOPIF、各类 Worker、网络子进程重建；不依赖代理认证缓存 |
| 入口与控制 | 配置 `users: []` 仅对新模型允许；WFP 未就绪禁止启动无密码实例；网站 401/403 不泄露节点凭据；跨组 CDP 连接失败；既有正常软件不受误拦 |
| 端口归属 | 占用、排除范围、IPv4/IPv6 动态范围、代理退出后的抢占、通配绑定、IPv4 映射地址、端口复用和残留规则；不结束占用端口的其它软件 |
| 两端出口 | 故意 DIRECT、漏配 listener 节点、DNS fallback、额外协议目标、代理缓冲上传仍被阻断；浏览器 UDP 与上游必要 UDP 区分 |
| 冻结与故障 | 长连接、WS/WSS、持续上传、服务/Agent 崩溃与卡死、BFE 状态异常、休眠、断网恢复、VPN/TUN 共存；动态放行撤销后无密码入口与上游均不可用 |
| Profile 与更新 | 原路径↔组路径、A↔B、版本升级、ABE/未知格式拒绝；Cookie/Local Storage/IndexedDB/合成登录可用；源目录更新中复制、磁盘不足、候选清理失败、替换各阶段崩溃 |
| 协调与恢复 | 并发命令、共享节点、组重命名/删除/换组、各日志阶段崩溃、磁盘写失败、关闭失败、回执过期后重放；日志不明确时维持暂停 |
| 安装与发布 | 权限、多用户/多会话、旧新 IPC 两个方向、升级卸载中断、残留目录/规则、Secure Boot 与内存完整性开启；不依赖全局强制放行 |
| 资源与诊断 | 四浏览器并发、100 次开关、端口/进程/候选目录回收、各组磁盘占用；端点故障不能误报保护通过 |

实际出口协议仍逐类验证 AnyTLS、Hysteria2、TUIC、VLESS/XHTTP、VMess/WebSocket、HTTP、HTTPS、SOCKS5；编译器接受字段不等于协议通过。某协议尚不支持时仅拒绝对应严格启动，不影响普通模式。账户环境继承/固定、迁移备份和界面轮询继续按已有要求回归。

证据以 `pktmon`、WFP 规则/审计和系统 DNS 观测为主；回环与虚拟接口须说明覆盖范围，“无日志”“没有收到 UDP”不能单独证明阻断。通过独立测试环境的阳性对照证明检测器有效。M3 再交付自部署 HTTPS 回显、权威 DNS、受限 DoH、STUN；只使用随机标识，不传账号凭据，本地报告保留 7 天、远端关联数据默认 15 分钟过期。未配置公网端点显示“未验证”，本机保护状态独立展示。

## 实施顺序、估算和停止条件

当前 `strictConfig.js`、共享 `chromePath` 的 WFP 原型和 `policy.example.json` 仍属于 v3 实验，不能仅删除 `users` 就用于 v4。实施必须新增有版本的策略模型：每组拥有自己的 Chrome 清单、mihomo 清单、用户和入口；旧策略不得自动转换成无密码策略。认证实验及失败报告保留，新能力另行记录，`network.getCapabilities` 继续返回 `M1_NOT_ACCEPTED`。

| 阶段 | 交付与通过条件 | 当前是否可推进 |
| --- | --- | --- |
| M1-A：离线准备 | 分组资源模型、规范路径/清单/磁盘峰值、策略编译与拒绝用例、新模型配置生成、启动前置条件、实验操作说明 | 可继续；不启动面向外部转发的无密码实例，不写 WFP，不迁移真实 Profile |
| M1-B：WFP 关键验证 | 两组路径、入口客户端限制、绑定/入站/CDP、上游约束、冻结/崩溃/现有连接，保留阳性对照和失败证据 | 等专用 Windows 测试环境；任何关键拒绝路径失败即停止后续集成 |
| M1-C：冷启动与路径兼容 | 使用已验证策略验证冷 WS/WSS、各目标、Profile 四类切换及更新中断；完整 M1 复审 | 依赖 M1-B；不把裸代理连通当作隔离通过 |
| M2：运行与恢复 | 受限管理服务/安装器、目录 ACL 和进程启动权限、分组生命周期、协议/DNS、强日志协调器和恢复、数据迁移 | M1 通过后进入产品实现；M1 期间只实现验证所需的最小权限原型 |
| M3：产品集成 | 在已有环境管理基础上补齐网络 IPC、模式界面、影响预览、状态、诊断及自部署端点 | 不提前开放严格能力 |
| M4：发行验收 | 多用户、安装升级卸载中断、兼容矩阵、资源循环、备份/恢复演练和发行产物 | 证据齐全后发布 |

本版先为 M1 剩余工作给出粗估：M1-A 2–4 人日、M1-B 5–8 人日、M1-C 4–7 人日，合计 11–19 人日，另留约 25% 风险缓冲；按一名熟悉 Windows 网络和项目的工程师全职投入估计，不含测试环境等待。v3 的 38–60 人日是旧全量基线，不能当作当前剩余工期；M1 后结合已完成环境管理、实际路径/协议兼容结果，重估 M2–M4。本路线不开发内核驱动，不再安排驱动签名资格调查，也不把项目程序代码签名列为前置条件。

M1-A 已新增[目录 ACL 只读报告](RUNTIME_ACL_REPORT.md)，检查程序目录内部和祖先的所有者/写入授权，复用文件清单和变更检查；它不验证运行用户的有效访问，也未接入启动准入。第三方来源核验单独记录，不建立项目程序“必须已签名”的启动条件。下一步整理 M1-B 最小实验操作清单，明确权限报告、身份登记和规则原型尚缺的验证项；取消代码签名要求不等于取消 WFP 权限、启动准入或实际隔离验收。

用户已确认没有专用 Windows 测试机或虚拟机。现在继续 M1-A；M1-B 前准备可恢复的 Windows 11 x64 测试环境，具备管理员权限、正常开启的 Secure Boot/内存完整性，以及测试用 Chrome/节点。没有该环境时不以日常主机试写规则替代验收。

以下任一缺口未解决，均保持严格模式不可用：跨组或未登记客户端可进入入口、mihomo 可走未批准出口、冻结无法阻止存量业务流、关键辅助进程未覆盖、Profile 路径/版本迁移不兼容、无法确认规则或恢复状态。不得自动退回共享无密码入口、增加全局 TUN、放宽回环范围、关闭浏览器安全功能或转入内核驱动。独立验证通过的环境管理和诊断可以继续交付。
