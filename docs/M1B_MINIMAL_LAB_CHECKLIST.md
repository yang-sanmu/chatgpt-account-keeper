## 1. 当前可以执行的准备

在仓库根目录构建实验工具，仅运行无 WFP 写入的离线检查：

```powershell
dotnet publish tools/network-isolation/NetworkIsolation.csproj -c Release -r win-x64
if ($LASTEXITCODE -ne 0) { throw 'NativeAOT publish failed' }
$lab = (Resolve-Path tools/network-isolation/bin/Release/net10.0-windows/win-x64/publish/network-isolation-lab.exe).Path
```

这些测试创建合成临时文件；ACL 阳性对照仅修改临时夹具权限，端口阳性对照只监听本机回环。没有浏览器/代理启动或 WFP 写入。原生测试有跳过时不能把该项记为已验证。

## 3. 最小实验布局

固定一个安装登记和一个普通测试用户，建立 A/B 两组，每组一个全新测试 Profile、一个活动代理和一个预登记 CDP 端口；A 组另备一个候选代次，用于验证候选隔离和回收。Chrome 完整副本使用编译器生成的各组路径，禁止硬链接。普通浏览器使用原安装路径和额外测试 Profile，不接触真实账号。

准备两个能在接收端区分的上游目标，以及一个不在允许列表中的目标。优先使用已知固定地址/端口的测试 TCP 上游，另用合成 UDP 客户端验证传输规则；UDP 规则实验通过不等于 Hysteria2/TUIC 协议验收。不要用文档 TEST-NET 占位地址作连通性目标，不需要先建设 M3 的整套公网诊断服务。

除基本 A/B 外，拒绝用例使用独立测试程序、另一普通用户以及未登记浏览器；每次都记录其路径、SID 和原始进程身份。相同路径/SID 的进程仍不是独立 WFP 身份，不以换 runToken 宣称进程隔离。

## 4. 按顺序执行的最小矩阵

下表是实验操作顺序；执行器命令见[专用说明](V4_WFP_LAB_EXECUTOR.md)。命令不会自动完成进程/Job、有效权限和捕获准备。每一行单独保存开始/结束时间、资源版本及证据；前置项未通过时，下游项记为 `blocked`，不跳过后算整体通过。

| ID | 操作 | 最小通过证据 |
| --- | --- | --- |
| B01 检测器与空载回收 | 在同一专用环境、相同测试目标和相关路径验证捕获能发现直连；随后安装/回读/回收无进程使用的 v4 默认拒绝规则，模拟一次安装失败 | 阳性对照确实到达目标；规则内容与资源键一致；失败事务不留下部分状态；回收后仅本轮资源消失，其它规则保持 |
| B02 默认拒绝 | 安装默认拒绝，再以受控合成程序测试登记路径的 TCP/UDP/IPv6 出站、入口客户端及绑定；每条路径都有未受该阻断影响的对照 | 浏览器路径和代理路径均不能外连；其它程序不能连接/占用登记入口或 CDP 端口；未登记端口和普通浏览器保持原有行为 |
| B03 精确许可 | 单独验证所属程序/用户的监听与 CDP 许可，再开放 A、B 的批准链路；用新建连接测试 A→B、B→A、普通程序→入口、错用户及回环别名 | 只有本组主 Chrome→本组入口、各组代理→各自上游、对应 Agent→登记 CDP 可用；辅助 exe 无业务许可；入口和 CDP 不允许通配监听或外部接入 |
| B04 两端出口 | 先用合成程序产生真实的错误上游、DNS、TCP/UDP/IPv6 请求，再在仅属于实验的配置中注入 DIRECT/错误目标作集成对照 | 错误目标被数据路径阻断且正确目标仍可用；若请求只被 `MATCH,REJECT` 或配置校验挡住，不能算 WFP 阻断证据；Chrome UDP 与代理必要 UDP 分别记录 |
| B05 冻结与存量流 | 建立长 TCP、WebSocket 和持续上传，包含代理已接收但尚未发出的数据；撤销 A 的两段业务许可，保留 CDP，随后关闭 A 并确认 Job 清零 | 两段均有规则事务和重新授权证据；冻结后的后续业务数据不再穿过受保护出口；接收端数据须与捕获对齐，区分提交前已在途数据；B 不受影响，CDP 可用于关闭 |
| B06 崩溃与控制异常 | 终止动态会话持有者；另测其卡死、Agent 崩溃/卡死、断网与休眠恢复；测试 BFE 状态无法确认 | 崩溃后动态许可清理且默认拒绝仍有效，记录实测时长；卡死不要求固定秒数冻结，但不得批准新启动/配置；恢复不扩大许可；无法确认状态时不显示“已阻断” |
| B07 候选、端口与清理 | 预占入口/CDP 端口；代理退出后用未登记程序尝试抢占；测试候选无业务许可；旧 Job/连接清理后再复用端口；最后删除副本并按保存清单回收 | 不终止占用软件；默认限制有效期间未登记程序抢占失败；释放后由该程序验证可重新使用端口；旧运行清理不能删除新代次许可；进程、端口及本轮规则无残留 |

B02 的合成程序必须放在专用夹具路径，通过正常受控登记生成规则；不能覆写已登记的 Chrome/mihomo 文件来冒充它们。B03 开始真实无密码代理前，先用不转发公网的合成监听器和客户端验证入口保护及用户条件；本组正确请求成功、其它客户端被拒绝后才进入代理实验。真实浏览器的首次请求、网络子进程重建和所有辅助 exe 仍须验证，合成程序不能代替它们。

B07 回收时先关闭准入、冻结业务并取得原进程/Job 关闭证明；保留默认拒绝直至不再需要保护的副本已删除或已撤销执行权限，再按本轮资源键清理。文件删除失败则保留拒绝和待清理记录；不能使用旧 v3 的清理键或全局重置防火墙。

## 5. 证据与判定

每轮使用独立 `runId`，记录提交 SHA、工具/Chrome/mihomo 版本、系统/防火墙/VPN 状态、捕获范围、登记路径与文件哈希、规则 GUID/内容、配置代次、进程身份/Job、目标和结果。原始报告留在测试证据目录，不能只保存一句“passed”。

网络证据至少包括已验证可见性的本机捕获、相关 WFP 规则/审计，以及受控目标的连接或接收记录；DNS 单独观察。回环、物理网卡、IPv6 和 VPN/虚拟接口分别做阳性对照。单纯超时、无日志、未收到 UDP、`inspect` 数量吻合或规则事务成功均不能单独通过。抓包及审计操作参考[实验工具说明](../tools/network-isolation/README.md#证据与阳性对照)，仅在专用环境配置，并保留原设置用于恢复。

结果统一记录 `not_run / blocked / passed / failed`，并附 `reason` 和证据文件路径。初始所有 B01–B07 均为 `not_run`；当前就绪结论为 `blocked`，原因是“无专用测试环境，首次写入前的运行/权限与检测准备未完成”。执行器的离线测试不计作 B01 通过，不创建预填成功的验收报告。

通过这张最小矩阵，只能说明对应版本/布局的基础路径获得实测证据。M1-B 还需覆盖现有 VPN/防火墙共存、四浏览器并发、100 次生命周期、重启后的持久规则、更多用户/会话及各目标传输。缺少相关环境或协议时如实保留未验证，不能取消主计划门槛。

M1-C 再使用已验证策略完成冷 HTTP/HTTPS/WS/WSS、Worker、各协议与 Profile 路径/更新兼容。M1 整体通过前，生产能力继续为 `M1_NOT_ACCEPTED`。
