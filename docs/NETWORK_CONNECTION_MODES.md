# 网络连接模式

Tauri 的“配置 → 网络配置”页提供全局网络模式，账号继续继承分组专用节点。三张模式卡分别展示链路示意图，分组预览按当前草稿显示链路；未保存的草稿有明确标记。

| 模式 | 分组绑定专用节点 | 分组未绑定节点（跟随网络配置） |
| --- | --- | --- |
| 直连 | 浏览器 → 专用节点 → 网站 | 浏览器 → 网站 |
| 系统代理 | 浏览器 → 系统代理 → 专用节点 → 网站 | 浏览器 → 系统代理 → 网站 |
| 指定中转 | 浏览器 → 中转 → 专用节点 → 网站 | 浏览器 → 中转 → 网站 |

图中省略本机私有 mihomo。当前普通模式“打开网页”的两个付款直连域名例外仍适用，具体见 `src/openPage.js`。本功能不改变严格网络隔离能力的验收状态。

## 配置与去重

设置存入 SQLite schema 8 的 `proxy_settings.network_config_json`；旧数据库升级前自动备份，默认 `system` 模式。旧 CLI JSON 后端读写 `config/proxies.json` 的 `network` 字段。

| 字段 | 含义 |
| --- | --- |
| `mode` | `direct` / `system` / `relay` |
| `relayProxyId` | 指定中转节点；仅 `relay` 模式使用 |
| `systemProxyUrl` | 手动系统代理入口；留空自动检测 |
| `outboundInterface` | 可选物理网卡名称，约束直连或中转模式的私有内核第一跳 |

中转来自“分组与代理”中的订阅及自定义节点池，选择列表只包含启用且未失效的节点。搜索按大小写不敏感的关键词匹配名称、协议及服务器地址。

专用节点的运行副本通过 `dialer-proxy` 连接前置代理。运行名使用节点 ID，清除导入配置里的旧 `dialer-proxy`，不修改保存的节点凭据或原文。主监听和测速临时内核都使用相同的链路编译器。

- 分组选择系统代理（未绑定节点）时，系统模式直接使用系统入口，不再追加前置系统代理。
- 分组节点等于中转 ID 时不添加 `dialer-proxy`。不同 ID 但配置相同的节点也去重，比较排除名称与链路、接口字段。
- 分组节点就是同一个系统代理入口时，识别本地回环地址别名并去重，保留分组节点的认证信息。
- 手动系统入口不能指向本工具实际监听的本地代理或控制端口。外部系统代理占用首选端口时，私有内核自动选择其它空闲端口段。

## 系统入口与直出边界

Windows 自动读取当前用户的固定代理配置；其他平台可读取代理环境变量，或使用手动入口。手动入口支持无认证 HTTP、HTTPS、SOCKS5；拒绝 URL 中的凭据、路径、查询参数和无效端口。系统配置无法读取或格式异常时，专用节点启动报错；检测到 PAC 时，专用节点须使用手动固定入口。系统代理未启用时遵循系统网络。

直连及指定中转不使用系统 HTTP 代理作为前置，但仍受操作系统路由、TUN/VPN、DNS 接管影响。可选网卡绑定作用于私有内核第一跳；未绑定节点的浏览器直连仍遵循系统路由。本工具不自动改其他代理软件、系统路由或 TUN。

## 保存与运行

IPC 1.5 新增 `network.getConfig` / `network.updateConfig`，`proxies.network` 为可选快照字段，沿用 `proxyState.changed` 事件。新版 Tauri 与 Agent 配套使用；`network.getCapabilities` 继续返回严格能力不可用。

保存在代理生命周期队列中进行；持有账号锁的任务、已登记的 BrowserRun、打开的浏览器或其他活动阻塞项未结束时返回 `RESOURCE_BUSY`。浏览器启动等待已进入队列的代理切换完成。

写入前验证中转引用；内核启动失败时恢复原网络设置并尝试恢复原运行配置，保留启动期间完成的其他节点导入。订阅刷新保留仍被选作中转的失效节点及引用，避免自动改出口；正在使用的自定义中转不能直接删除。

启动先确认监听端口，再通过本地控制接口应用生成的同一份配置，等待内核应答完成。这个应答发生在内核转入 Running 后，避免端口已开放、转发尚未初始化时首个请求收到 502。启动检查不访问网站。

测速前检查固定控制端口是否被其它程序占用；被占用时直接报错，不向该端口发送配置。测速就绪检查与启动使用同一份配置快照。

## 验证入口

- `test/networkConnectionModes.test.js`：三种路由、两个去重场景、默认出口、失效中转、系统入口解析、网卡第一跳、SQLite 持久化与 v7 升级、IPC 活动保护。
- `test/mihomoReadiness.test.js`：控制端口开放但配置未确认时保持等待；配置拒绝、内核退出、无响应均保持未就绪。
- `test/agentBackgroundWiring.integration.test.js`：真实 Agent 的配置读写、幂等重放、bootstrap 快照、无效中转拒绝。
- `app/src/pages/network/network-page.test.tsx`：示意图、两类节点模糊搜索、预览去重、保存、浏览器占用。
- `test/networkConnectionModes.integration.test.js`：显式设置 `GPT_ACCOUNT_CONNECTION_LAB=1`，用真实 mihomo 与回环代理/网站验证三种模式、相同节点只转发一次、失败启动回滚。可用 `GPT_ACCOUNT_CONNECTION_LAB_MIHOMO` 指定内核绝对路径；默认使用已有 release-input 内核。

链路测试用本机夹具验证转发次数；用户的 AnyTLS/Hysteria2 与真实专用节点组合仍需在实际网络中测试。
